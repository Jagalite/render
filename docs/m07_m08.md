# M07 rendering breadth and M08 animation profiles

This is the implementation contract for the M07/M08 work, including its M06
modeling prerequisite. Completion is recorded separately in
[the execution ledger](m07_m08_execution.md) and
[the evidence index](../evidence/m06-m08/README.md). The canonical milestone gates
in [architecture.md](architecture.md) remain unchanged.

## Authoring and persistence

All features are typed Rust data and ordinary revision-checked document commands.
There is no editor-only mutation path or foreign computational runtime. Immutable
source assets remain separate from disposable render geometry. Canonical JSON and
native journal envelopes preserve clips, graphs, attachments and policies; browser
OPFS uses the same Rust document engine. Imported text never becomes executable
instructions. Existing OBJ/glTF adapters retain their separately declared limits:
these milestones do not add glTF animation, arbitrary shader imports, OpenVDB or
Blender compatibility.

Snapshot versions add optional fields without changing older empty-field digests:

| Version | Added authored semantics |
|---|---|
| 3 | Curve/point assets and entity bindings |
| 4 | Sparse media assets and bindings |
| 5 | Guides, children and persistent groom roots |
| 6 | Clips, rigs, skins, morphs and quaternion transform operations |
| 7 | Named render views, bakes and color/denoise pipeline |
| 8 | Typed advanced surface and opacity models |
| 9 | Typed geometric displacement |
| 10 | Procedural graphs, entity bindings and modeling correspondence receipts |

Unsupported versions, missing references, stale source revisions and invalid
profiles are rejected. `ModelMesh` pins its source mesh; `BakeProcedural` pins its
source graph and retains that graph after producing an editable polygon asset.
The serialized modeling command uses `operation: "model_mesh"` and `operator`
for the nested typed modeling operator. `SetAnimation`, `SetGroom`, `SetImaging`,
`PutGeometry`, `PutVolume` and `SetProcedural` use the same transaction engine.
See [M06's operator contract](m06_modeling_contract.md).

## Backend support

| Capability | Native Rust CPU / browser Rust Wasm | Metal / browser WebGPU |
|---|---|---|
| Curves, points, guide/child grooms | Bounded evaluated polygon sweeps | Same derived meshes and existing surface profiles |
| Sparse RGB media | Exact cell extinction/emission; bounded point-light single scattering | Explicit `unsupported_profile` |
| Ideal dielectric, conductor, single coat and alpha | Finite-depth extended BSDF integrator | Explicit `unsupported_profile` |
| Displacement | Uniform triangle dicing and geometric normals | Same derived geometry with supported surface materials |
| Views, albedo/depth/normal/object passes, UV bakes | Rust imaging workflow | Individual supported raw scene renders; no GPU imaging pipeline |
| D65 sRGB/Display-P3 and bilateral-v0 | Rust color matrices and spatial filter | CPU postprocessing only |
| Clip/rig/LBS/morph evaluation | Same exact-time Rust evaluation | Evaluated geometry rendered at individual times |
| Shutter sequence integration | Rust CPU temporal sample accumulation | No GPU sequence accumulation API |

A successful CPU render is not advertised as GPU support. The GPU material packer
still emits five shading texture descriptors; height textures are evaluator inputs.
Raster preview retains its earlier limited profile.

## Geometry and transport policies

Curves retain stable control IDs, radius and tilt with polyline, chained cubic
Bezier or clamped rational B-spline bases. Rational knot insertion and homogeneous
control-hull subdivision bound approximation; tubes use transported frames and
explicit closed-loop twist correction. Points retain IDs and radii, with bounded
polygon sphere realization. Conversion receipts record source/policy digests,
sample counts, bytes and derived ranges. No analytic curve intersections or
self-intersection cleanup is implied.

Groom roots name an entity, topology digest, stable triangle corner IDs and
barycentric coordinates. Guides and length/radius/twist child parameters remain
authored data. Position deformation updates roots; topology changes require
explicit rebinding. Hidden anchors remain available to dependency evaluation.
The named sweep-surface material is usable hair geometry, without a physical fiber
BSDF. At most 256 guides and 2,048 total strands share aggregate sampling limits.

Sparse cells use integer coordinates, metric voxel dimensions and zero background.
RGB coefficients are per world meter even under scaled transforms. Overlapping
cells sum extinction/emission. Ordered ray intervals integrate Beer attenuation
and emission exactly; midpoint quadrature integrates Henyey-Greenstein point-light
single scattering. Limits are 16,384 occupied cells per scene, 131,072 overlap
entries and 65,536 quadrature steps per ray. Indirect in-scattering is unsupported.

Advanced surfaces use ideal smooth dielectric refraction/reflection with radiance
eta-squared transport; conductor GGX uses Schlick Fresnel derived from eta/k;
clearcoat attenuates the base through two Fresnel factors and adds a single GGX
interface. There is no multiple scattering between coat layers or directly sampled
glass point-light caustics. Alpha blend is stochastic coverage; masks use an
explicit cutoff. Alpha image lookup uses the base mip level. Transparent traversal
is limited to 64 surfaces. Finite path depth is a named bias, not an unbiasedness
claim. Normal maps affect reflection shading, while refraction uses geometric
interface normals.

Displacement supports constant, UV wave or linear-data image heights in object
meters, 0–6 dicing levels and at most 524,288 vertices. Shared-edge crack detection
rejects inconsistent height/normal seams. UVs interpolate; shading frames are
recomputed. Other attributes and loose elements require a future transfer profile
and are rejected. Source topology remains unchanged.

## Imaging semantics

Scene render images remain linear-sRGB. Separate tagged display artifacts apply
exposure, optional luminance Reinhard, explicit gamut preservation/clipping and
D65 linear/encoded sRGB or Display-P3. RGB-to-XYZ matrices are derived in Rust from
primary chromaticities. The reference tests use independently tabulated W3C
rational matrices and signed transfer vectors.

`bilateral-v0` has radius 1–4, explicit spatial/luminance/normal/relative-depth
weights and hard object-ID boundaries. It is a biased spatial filter without
temporal history, ICC or LUT support. Tests cover constants, edge preservation
and noise-error reduction. Views can hide selected entities while preserving
required dependency geometry. At most 16 views and 16 bakes share a retained-image
byte preflight.

UV bakes provide albedo, emission and geometric world normals, a coverage mask and
revision/request/output digests. Pixel-center sampling supports a non-overlapping
[0,1] atlas up to 2048 squared, with an explicit work cap. Shared triangle edges
have first-owner rules; interior overlaps, degenerate charts and empty coverage
are errors. Reflected world-normal bakes follow transformed winding. There is no
atlas generation, dilation or indirect lightmap bake in this profile.

## Animation semantics

Time is a reduced signed rational number of seconds. Frame conversion, ordering,
offset/rate arithmetic and repeat use checked rational operations. Clips retain
step, linear or cubic Hermite interpolation, with derivatives per second and
explicit clamp/repeat extrapolation. Euler order is authored. Quaternion linear
interpolation is shortest-arc slerp; cubic is normalized component Hermite, with
zero-length results diagnosed. Pose deltas append T*R*S to authored/rest affine
transforms, preserving existing shear rather than decomposing it.

Stable joint IDs define parent order, rest transforms and validated inverse binds.
Constraints execute in explicit dependency order: CopyPosition and analytic direct
root–mid–tip TwoBoneIk with goal, pole and tolerance. Cycles, conflicting writes,
unreachable goals, singular transforms and excessive residuals carry causal
constraint diagnostics. The initial skin profile is 1–8 normalized influences per
stable point, explicit mesh bind, and LBS after sparse morph offsets. Bindings
require explicit triangle realization before deformation; the character fixture
performs this through M06's ordinary modeling command. Geometric output normals
are recomputed. Topology animation, general constraints, dual-quaternion skinning
and retargeting remain distinct future profiles.

Random access evaluates disposable snapshots and cannot alter the published rest
state. `PreviewAt` pins the authored revision and does not qualify a static variant
for commit. Sequences contain up to 1,024 strictly increasing times. Shutters have
exact relative open/close times and 1–32 midpoint samples. Each sample independently
evaluates rigid transforms, morphs and skinning, then accumulates linear radiance.
Depth, normal and object passes use nominal time. Cancellation can leave explicitly
partial completed-frame output; no partial sequence is reported as complete.

## Reproduction and provenance

Start the local Rust server and isolated Chrome CDP as in [agent_alpha.md](agent_alpha.md),
then run `python3 scripts/validate-milestones.py`. It uses a fresh
`artifacts/m06-m08/run-*` directory and never regenerates historical evidence.
The runner executes all 17 foundation gates, seven native feature workflows,
browser OPFS and renderer checks, inherited textured PBR regressions and independent
native/browser pass comparisons. `/usr/bin/time -l` records process RSS/footprint;
workflow reports record serialized bytes, derived growth and evaluation time.
These are measurements of small fixtures on one machine, not general performance
or allocator bounds. Linux and Windows are compile checks only.

The fixtures in `crates/core/src/feature_fixtures.rs` are newly authored synthetic test
geometry, materials and animation. Existing external texture fixtures retain their
original provenance manifests. Computational implementation is maintained Rust;
WGSL and browser bindings are generated from the existing Rust kernel/build inputs.
No dependencies are added beyond the already recorded static PBR dependency slice.
