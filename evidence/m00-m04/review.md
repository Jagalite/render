# Foundation implementation review

Scope: the complete M00–M04 implementation relative to the documentation-only baseline `a5e1787`. Review focused on transaction publication, candidate isolation, layers, queue lifecycle, native worker ownership, CLI project integration, geometry/rendering boundaries, ABI ownership and evidence claims. This was a code and behavioral review, not an external security audit or additional-device certification.

Six concrete findings were corrected before the implementation commit:

| Priority | Finding and trigger | Correction and regression |
|---|---|---|
| P1 | `api <project>` wrote the project root while `jobs <project>` opened a separate `journal/` directory. A job could render the demo instead of the API-authored document. | Both commands open the same native package root. `jobs_pin_the_document_written_through_the_project_api` persists an API edit, starts the host and verifies the job's pinned revision and entity data. Legacy nested packages return an explicit layout diagnostic. |
| P1 | Opening a second job host ran interrupted-job recovery while the first host could still have a live worker. Short publication locks did not protect worker ownership. | A nonblocking OS worker lease is held for the host lifetime, through worker shutdown. `second_host_cannot_recover_an_active_worker` rejects a second open and permits reopening after the first host exits. |
| P1 | `durable_execute` returned a retained in-memory receipt before consulting the requested storage adapter. A previously executed request, or an imported receipt from another store, could skip publication. | Recovery/conflict checks precede reuse. Unpublished retained requests are persisted without executing their commands again. `durable_retry_publishes_to_the_requested_store` tests failure, successful retry, deduplication and a fresh destination. |
| P2 | Clearing an entity's mesh while composing an early hidden layer made a later `hidden: false` unable to restore it. | Visibility is resolved across the complete layer stack before hiding geometry. `later_layer_restores_hidden_geometry` verifies later-layer precedence and unchanged authored references. |
| P2 | Cancelling queued jobs left their IDs in the bounded queue. Repeated submit/cancel cycles exhausted admission despite no live work; repeated cancellation also consumed retained events. | Cancellation removes queued IDs and emits events only for state transitions. `cancelled_jobs_release_queue_capacity_and_retries_preserve_events` exercises a one-slot queue repeatedly. |
| P2 | Idempotency capacity was checked only at prepare time. Multiple no-op candidates could retain the same authored base and commit beyond the limit. | Commit checks the current retention limit after duplicate detection. `prepared_noop_candidates_cannot_overfill_retention` exercises two prepared candidates at capacity while preserving accepted retries. |

The core regressions run natively and under WASM. Native-only host regressions exercise actual filesystem locks and persisted project state. `job_host_conformance.json`, `api_conformance.json`, `document_conformance.json`, `durability_faults.json` and the validation logs retain the results.

No additional blocking finding remained in the reviewed paths after these fixes. Published limitations remain: trusted local clients, experimental ABI/storage formats, named diffuse/interchange profiles, whole-asset editing conversion, conservative conflicts with external writers, estimated admission budgets, and macOS/Chromium runtime coverage. Linux/Windows are compile checks only. Binary image formats are marked binary in Git attributes to preserve their bytes across checkout line-ending settings. Image outputs are observed evidence; no golden image or acceptance tolerance was changed to pass this review.
